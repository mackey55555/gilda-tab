# gilda 注文管理アプリ — 仕様書 (v0.1)

## 1. 概要

バー「gilda」（営業: 木・金・土 20:00–24:00）で使う注文管理Webアプリ（PWA対応）。
現在スタッフが紙メモで行っている「客名 → 注文金額 → 正の字 → 手計算で会計」の運用をデジタル化し、
**何が・いつ・どれだけ売れたか** を記録・集計できるようにする。

- 操作するのは**スタッフのみ**（客は操作しない）
- 営業用画面は**スマホ前提**、管理用画面は**PC前提**でUIを完全に分ける

## 2. 技術スタック

| 項目 | 選定 |
|---|---|
| フレームワーク | Next.js (App Router) + TypeScript |
| UI | Tailwind CSS |
| BaaS | Supabase (Postgres / Auth / RLS) |
| ホスティング | Vercel |
| PWA | Serwist（manifest + Service Worker、ホーム画面追加対応） |

- 認証: Supabase Auth（メール+パスワード）。スタッフ=ログインユーザー
- オフライン: 本格対応はしない。楽観的UI更新＋失敗時リトライ表示のみ（PWAはインストール性と起動速度が目的）

## 3. データモデル

```
staff        … Supabase auth.users に対応するプロフィール (id, name, role)
products     … 商品マスタ (id, name, price, category, sort_order, is_active)
business_days… 営業日 (id, date, opened_at, closed_at, status)
tabs         … 伝票 = 1人1枚 (id, business_day_id, guest_name, status[open/paid], payment_id, created_at)
order_items  … 注文明細 (id, tab_id, product_id nullable, name_snapshot, price_snapshot, qty, staff_id, created_at)
payments     … 会計 (id, business_day_id, total, staff_id, paid_at)
```

設計上のポイント:

- **伝票は常に1人1伝票。グループ概念は持たない。** まとめるのは会計時のみ:
  `payments` を1件作り、対象の複数 `tabs.payment_id` に紐づけて一括クローズする（1会計 : N伝票）
- 明細は `name_snapshot` / `price_snapshot` を持ち、後のマスタ変更・削除に影響されない
- マスタ未登録の注文用に `product_id = null` の**フリー金額明細**を許可（名称は「その他」等）
- 会計取り消し: `payments` を削除し、紐づく伝票を `open` に戻すだけ（明細は不変）
- 集計は伝票・明細ベースで行い、会計のまとめ方に依存しない

## 4. 画面構成

### 4-1. 営業用（スマホライク）`/floor`

**実質1画面**。薄暗い店内・立ち・片手操作前提。ダークテーマ、タップ領域は最低44px。

1. **伝票一覧（ホーム）**
   - 現在openな伝票をカードで一覧（客名・現在合計・最終注文からの経過時間）
   - 右下に大きな FAB「＋お客さん」→ 即座に伝票作成。**名前は後入力可**（仮名「客A」「客B」を自動採番し、タップでリネーム）
   - 「まとめて会計」モード: 伝票を複数チェック → 合算金額表示 → 一括クローズ
2. **伝票詳細**（一覧からタップ、ボトムシートまたは全画面遷移）
   - 上部: 客名（タップで編集）・現在合計
   - 中央: **商品グリッド**。カテゴリタブ＋よく出る商品を上位固定（sort_order）。タップで+1
   - 明細リスト: 各行に − / + ボタンで数量調整、スワイプ or 長押しで削除
   - 「その他 ¥直接入力」ボタン（テンキー）
   - 「会計する」→ 合計確認 → クローズ
   - 目標: **注文追加を2タップ以内**

### 4-2. 管理用（PCライク）`/admin`

サイドバー＋メインのダッシュボード型レイアウト。

1. **売上集計**
   - 日別売上（期間指定、折れ線/棒）
   - 商品別ランキング（売上・数量、期間指定）
   - 時間帯別売上（20時台〜24時台）
   - 営業日別の詳細（伝票一覧・明細ドリルダウン）
   - CSVエクスポート
2. **商品マスタ**: CRUD、価格、カテゴリ、表示順、有効/無効（削除ではなく無効化を基本にする）
3. **スタッフ管理**: 一覧、招待（Supabase Auth invite）、role変更
4. **営業日管理**: オープン/クローズ操作、過去営業日の閲覧

## 5. 権限

- 全スタッフ: `/floor` の全操作
- role=admin のみ: `/admin` 全画面（マスタ・スタッフ管理・集計）
- RLSで担保（business_day / tab / order_item は認証済みスタッフのみ読み書き）

## 6. 未決事項（仮決め済み・要確認）

| 項目 | 仮決め |
|---|---|
| 支払方法の記録（現金/PayPay等） | v0.1では記録しない。payments に method カラムだけ用意しnull許可 |
| 割引・サービス | フリー金額明細のマイナス入力で代用 |
| 税 | 全て税込価格として扱う |
| 伝票の日跨ぎ | 営業日クローズ時にopen伝票が残っていたら警告 |
| 複数端末同時操作 | Supabase Realtimeで伝票一覧を同期（週3営業・端末2〜3台想定なので無料枠内） |

## 7. 実装順序（チェックポイント）

1. Supabaseスキーマ＋RLS＋seed（商品数件）
2. 認証＋`/floor` 伝票一覧・作成・詳細・注文追加（コア動線）
3. 会計（単独→まとめて会計）
4. `/admin` マスタ（商品・スタッフ）
5. `/admin` 集計
6. PWA化・ダークテーマ調整・実機検証（木〜土いずれかの営業で試験運用）

各ステップ完了ごとに実機（スマホ）で動作確認してから次へ進む。
